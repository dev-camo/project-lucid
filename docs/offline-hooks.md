# Offline hook registry

Every point where the offline adapters (namespace `ProjectLucid.Offline`) divert an original member. Decision D2: a hook is a check of the central switch `ProjectLucid.Offline.OfflineAdapters.Active` (`Packages/com.hardlight.hlunitycore/Runtime/Offline/OfflineAdapters.cs`) in the hooked method, with the original body kept verbatim after it, so the original is always compiled and its generated names stay exact. Three shapes are used. Most hooks are a guard at the top that runs the adapter and returns. Mid-method hooks (H-001, H-010, H-013, H-017, H-053) sit where the original diverges, after statements the original still runs first. Fall-through bookkeeping (H-031, H-033..H-035, H-037, H-039..H-042) does adapter work such as a stop check or remembering a manager, then continues into the original body. Each hook in source carries a comment `Offline hook H-nnn: ...`; search for `OfflineAdapters.Active` or `Offline hook` to find them all.

`tools/tests/test_offline_hooks.py` checks that this table and the source agree. Add a row here for every new hook, and never reuse an ID.

No `#if` is left for a hook. The original code compiles everywhere, including the five unresolved native imports of H-011 and H-058..H-061, which are declared like Cloud_MacOS declares its imports (`[PreserveSig] static extern` with no recovered module, under `#pragma warning disable 0626`).
